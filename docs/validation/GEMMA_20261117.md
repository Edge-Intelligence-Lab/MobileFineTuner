# Gemma regression after Qwen/shared-path changes — 2026-11-17

Training code tested at `af80d13ebe1f10de9bc991e6bd27d9253850f928` in PR #12.
The test uses Apple M2 / 16 GiB, native CPU Release builds with Accelerate,
real Gemma 3 270M and Gemma 3 1B-PT checkpoints, and a WikiText-2 excerpt.
The shared SafeTensors loader's default FP32 base storage is used.

## Relevant changes

The Gemma decoder architecture is retained. Shared FP16 conversion, large-vocab
loss-gradient precision and LoRA operations affect this path. Gemma injection
now binds configured dropout and a per-injection seed instead of silently
ignoring dropout or sharing a static RNG across model initializations. Saved
adapters restore dropout. Checkpointing rejects nonzero LoRA dropout to avoid
stochastic recomputation, whether enabled before or after injection.
The default Gemma example dropout remains zero.

## Real-weight checks

All four cases use sequence length 16, batch 1, rank 2, alpha 4, all seven
attention/MLP projections, learning rate 2e-4, no warmup, and three optimizer
updates. Each step saves an adapter snapshot.

| Model/path | Dropout | Step losses as logged | Adapter tensors | Result |
| --- | ---: | --- | ---: | --- |
| Gemma 3 270M ordinary | 0 | 6.75599, 9.061, 5.603 | 252 | Passed |
| Gemma 3 270M ordinary | 0.05 | 6.75599, 9.063, 5.592 | 252 | Passed |
| Gemma 3 1B-PT ordinary | 0 | 6.27291, 7.817, 5.218 | 364 | Passed |
| Gemma 3 1B-PT checkpointed + streamed attention | 0 | 6.27292, 7.817, 5.218 | 364 | Passed |

The checker validates finite loss and every saved adapter tensor, all 126/182 B
matrices nonzero, every adapter tensor changed between steps 1 and 3, and final
export equal to the step-3 snapshot. The 270M dropout run changes adapter tensor
values relative to dropout zero. The first 1B loss agrees between ordinary and
checkpointed/streamed paths within 1e-3. Different minibatches explain why loss
need not decrease at every step; this is not a quality or convergence benchmark.

Five focused CTest checks pass: model memory optimization combinations,
optimizer norm precision, LoRA linear derivatives, Auto API/dropout/checkpoint
guards, and Gemma adapter roundtrip. The model-memory test includes all eight
checkpointing/streamed-attention/offload combinations with tiny models; the
real-weight checks above do not claim real-model offload qualification.

No regression was observed for the covered short training paths. This does not
establish long-duration Gemma stability, full-size HF trajectory parity,
physical-phone behavior, or every possible model/configuration combination.

## Reproduce

Build each example separately (`gemma_3_270m_lora_finetune` or
`gemma_3_1b_pt_lora_finetune`):

```bash
cmake -S "examples/$GEMMA_EXAMPLE" -B "runs/$GEMMA_EXAMPLE-build" \
  -DCMAKE_BUILD_TYPE=Release -DUSE_BLAS=ON -DOPERATORS_WARNINGS_AS_ERRORS=ON
cmake --build "runs/$GEMMA_EXAMPLE-build" --target train -j2
VECLIB_MAXIMUM_THREADS=4 OMP_NUM_THREADS=4 \
"runs/$GEMMA_EXAMPLE-build/train" \
  --model_dir "$GEMMA_MODEL_DIR" --data_dir "$WT2_EXCERPT_DIR" \
  --seq_len 16 --batch 1 --grad_accum 1 --max_steps 3 \
  --rank 2 --alpha 4 --lr 2e-4 --warmup_ratio 0 \
  --lora_dropout 0 --save_every 1 --output_dir runs/gemma-regression
```

For the 270M dropout check, use `--lora_dropout 0.05`. For 1B memory mode,
retain dropout zero and add `--activation_checkpointing
--memory_efficient_attention`. Use a separate output directory for each case.

Local raw logs, resource samples, commands, snapshot checks and status are under
`runs/gemma_regression_20261117/` (ignored runtime evidence). Model weights,
datasets and adapters are external runtime assets and are not source files.
