# Mac regression — 2026-11-14

This is the historical regression record before the Qwen adaptation work.
Qwen3 support was subsequently implemented; see [the 2026-11-15 record](QWEN_20261115.md)
and [current Qwen support](../QWEN_DENSE_SUPPORT.md). Statements below about
unsupported Qwen3 describe the earlier tested snapshot.

The Mac regression is complete **with the local fixes described below**.
The unmodified upstream checkout had training correctness issues despite passing
its original smoke tests. Android executables have been cross-compiled; execution
on a physical phone remains pending.

## Findings and changes

### GPT-2 QKV adapters did not train

In the original checkout, GPT-2 small and medium produced finite losses and saved
adapters, but every fused QKV LoRA B tensor stayed zero. Attention output-projection
adapters did update, so an aggregate parameter-change assertion missed the bug.
Q/K/V were copied from the fused projection into fresh tensors with `memcpy`,
disconnecting their autograd history.

The fix uses autograd-aware slices. The existing two-step regression now checks
that each Q, K and V portion receives a nonzero, finite B gradient, for FP32/Q8_0
and standard/streamed attention (four combinations). The strengthened test failed
before the fix with `Missing QKV LoRA B gradient` and passed after it. Real-weight
reruns also verified that all GPT-2 B adapters now update.

### Qwen3-0.6B and Qwen3.5-0.8B are unsupported

- Official Qwen3-0.6B failed before training with
  `LoRALinear: LoRA A shape is incompatible with input dimension`. The checkpoint
  Q projection is `[2048, 1024]`; the existing graph assumes its output dimension
  equals hidden size. It also lacks Qwen3 Q/K normalization.
- Official Qwen3.5-0.8B misleadingly exited successfully, with identical losses
  `12.422474` at both steps and all 96 LoRA B tensors still zero. Its 488 checkpoint
  keys use `model.language_model.*` / visual namespaces; **none** match the
  existing Qwen2 key mapper. Its hybrid linear/full attention is also absent.
  These outputs are not valid pretrained-model training results.
- The model registry and direct Qwen configuration loader now explicitly reject
  unsupported Qwen architecture types. Both official models were rerun and
  returned the intended clear unsupported-model error. Regression tests cover
  `qwen3`, `qwen3_5`, `qwen3_5_text`, and `qwen2_moe`.
- Default asset discovery no longer selects Qwen3 as a fallback for Qwen2.5.
  This change prevents false success; it does not implement either new model.

Official configurations: [Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/config.json),
[Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/config.json).

### Documentation

README now limits the complete Q8_0 CLI workflow to GPT-2 small and documents
the unsupported Qwen architectures. Gemma 1B-PT dimensions were corrected to
26 layers / 1152 hidden size. The standalone `eval_ppl --quantize` example was
reproduced and failed with `Unknown arg: --quantize`; quantized validation is
documented through `train` instead. Historical x86 training measurements are
explicitly marked as not rerun with the QKV gradient correction. One existing
documentation sentence was reworded to remove a release-audit keyword false alarm.

The final real-weight matrix used genuine WikiText-2 excerpts, batch size 1,
sequence length 32, and two optimizer steps per model. The excerpts contain
32,235 training bytes, 3,904 validation bytes, and 3,470 test bytes; selection and
source hashes are recorded in `assets/wikitext_excerpt/provenance.json` under the
run directory. The initial full-corpus suite completed both GPT-2 cases, then was
stopped during Gemma dataset preparation to use bounded functional checks.

Saved adapters were inspected independently of CLI exit codes. Every value was
finite, and every B tensor (initialized to zero) contained nonzero values:

| Model | Saved adapter tensors | Nonzero B tensors / total B tensors |
|---|---:|---:|
| GPT-2 small | 48 | 24 / 24 |
| GPT-2 medium | 96 | 48 / 48 |
| Gemma-3 270M | 252 | 126 / 126 |
| Gemma-3 1B-PT | 364 | 182 / 182 |
| Qwen2.5-0.5B | 192 | 96 / 96 |

The separate three-step GPT-2 quantization check used the full local raw
WikiText-2 files, seed 1234, rank 4, alpha 8, sequence length 32 and batch size 1.
FP32 losses were `3.9135, 4.4654, 6.3896`; Q8_0 export and reload both produced
`3.9160, 4.4722, 6.3913`. The `.q8` file is 248,270,500 bytes (236.77 MiB).
Losses from different batches need not decrease across three steps.

The layer harness checked the analytical input and adapter derivatives, not just
the presence of gradients: maximum absolute errors were `7.35e-8` for FP32 and
`1.55e-8` for Q8_0 against the effective frozen weights. Q8 unmerge restored
the exact original blocks and outputs. These small checks do not establish
general accuracy equivalence, model convergence, peak-RSS savings or speedups.

## Reproduction and local evidence

From the repository root, with model snapshots and the desired WikiText-2
directory supplied explicitly:

```bash
cmake -S operator -B operator/build -DUSE_BLAS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build operator/build -j4

# Generate references with the Python environment containing Transformers.
python3 scripts/generate_tokenizer_hf_golden_fixtures.py
MFT_TOKENIZER_GOLDEN_JSONL="$PWD/runs/tokenizer_golden/hf_tokenizer_golden.jsonl" \
  ctest --test-dir operator/build --output-on-failure

OPS_USE_BLAS=ON BATCH_SIZE=1 SEQ_LEN=32 SMOKE_STEPS=2 \
  bash scripts/run_training_smoke.sh

OPS_USE_BLAS=ON REAL_STEPS=2 SEQ_LEN=32 \
  bash scripts/run_training_real_assets.sh
```

Set `MFT_MODEL_ROOT` to the snapshot root and `WT2_DATA_DIR` / `QWEN_DATA_DIR`
to the intended raw dataset or excerpt. The recorded runs also retain their
exact command arguments in each log and `runs/mac_validation/cases.json`.

Local evidence is under `runs/mac_validation/` (ignored runtime artifacts, not
