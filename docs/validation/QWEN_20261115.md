# Qwen adaptation validation — 2026-11-15

This is a historical dense-model record. Qwen3.5 was added subsequently; see
[hybrid validation](QWEN35_20261115.md) and the [current integration audit](PR_INTEGRATION_20261117.md).

**Follow-up:** Qwen3.5 pure-text support was subsequently implemented and checked.
See [the Qwen3.5 record](QWEN35_20261115.md); earlier Qwen3.5 rejection results
below describe the intermediate dense-only implementation.

This record covers the local Qwen2/Qwen3 dense decoder adaptation on top of
upstream `be95a289d9cd5ecd93b6fab7fdc3c4551c3f9fb1` and the earlier Mac regression
fixes. The upstream `main` reference was checked again and still pointed to that
commit. Changes remain local on `validation/macos-20261114`; no PR has been pushed.

## Result and scope

Qwen3-0.6B now correctly loads official pretrained weights, injects LoRA using
actual layer dimensions, completes short real-text training, and saves/loads
standard PEFT adapters. Qwen2.5-0.5B remains compatible. This is configuration-
driven support for the Qwen2/Qwen3 dense text architectures, not support for every
Qwen-branded checkpoint. See [the implementation contract](../QWEN_DENSE_SUPPORT.md)
for the supported attention/RoPE features and explicit exclusions.

Environment: Apple M2 / 16 GiB, macOS 26.5.1, Apple clang 17.0.0, CMake 4.0.3,
Release with Apple Accelerate; host references used Python 3.13, PyTorch 2.10.0,
Transformers 4.57.1, PEFT 0.18.0 and tokenizers 0.22.2. The native runtime remains
pure C++; nlohmann/json 3.12.0 is vendored internally with its MIT license.

## Changes

- Model config controls head dimensions, projection widths, Q/K normalization,
  biases and shared/independent output heads. Complete checkpoint loading checks
  required keys and shapes before replacing weights.
- LoRA selects exact module targets, including MLP and all-linear targets, and
  derives shapes from actual layer matrices. The Auto API forwards target lists
  exactly. Adapter dropout now acts on the adapter branch with advancing seeded
  RNG state and an explicit evaluation mode.
- Adapter files use standard PEFT config, keys and tensor orientation. Both
  directions of interoperability were exercised. Failed adapter validation
  preserves the currently installed adapter.
- The maintained Qwen CLIs support target selection and restoring adapters for
  further training, and write both legacy binary and standard PEFT exports.
- SafeTensors metadata is parsed structurally; `__metadata__` is excluded from
  tensor names, malformed/truncated payloads are rejected, and output-head layout
  is explicit.
- Expanded tokenizer references caught a whitespace-boundary bug shared by
  Qwen2/Qwen3. The whitespace branch now follows the negative-lookahead split and
  retains a single whitespace prefix for the next token where appropriate.
- A new FP16 checkpoint edge test found that the existing scalar conversion
  halved nonzero subnormals. The shared conversion formula was corrected, and
  checkpoint promotion now uses that common conversion rather than dropping
  subnormals. Exhaustive host comparison covered all 65,536 FP16 bit patterns.

## Independent Transformers/PEFT comparisons

Five tiny models cover Qwen2/Qwen3, shared/independent output heads, non-square
GQA projections, Qwen3 attention biases, Q/V-only, K-only, O-only, Q/K/V/O, and
all-linear LoRA. Each is tested with standard and streamed attention: ten cases.
Every logits element, every adapter gradient, one Adam update, post-update
logits, and adapter reload are checked. Initial A and B are both nonzero so both
derivatives are exercised. Causal loss shifting matches on the two sides.

| Quantity | Largest observed absolute difference across ten tiny cases |
|---|---:|
| Logits | 2.98023e-8 |
| Adapter gradients | 1.86265e-9 |
| Adam-updated adapter parameters | 3.63216e-8 |

The tiny logits tolerance is `3e-5 + 3e-4 * abs(reference)`; gradient and update
comparisons have separate bounds in `test_qwen_hf_parity.cpp`. Post-update C++
adapters were loaded by PEFT and independently evaluated in all ten cases.

Full official checkpoint **forward** comparisons use a two-sequence, four-token
batch with nonzero attention adapters and one masked token. These compare
logits and loss, not full-checkpoint gradients or a benchmark dataset score:

| Official checkpoint | Standard attention max absolute logit difference | Streamed attention |
|---|---:|---:|
| Qwen2.5-0.5B | 5.81697e-4 | 5.14746e-4 |
| Qwen3-0.6B | 7.72476e-5 | 6.94990e-5 |

Full-checkpoint logits use `1e-3 + 1e-4 * abs(reference)` as the declared bound.
Base snapshots and upstream SHA-256 verification are retained under the earlier
`runs/mac_validation/assets/` directory.

## Real-text training and artifact checks

Native CLI training uses the genuine WikiText-2 excerpt described in
[the earlier record](MACOS_20261114.md), sequence length 16, batch size 1, rank 3,
alpha 6, zero LoRA dropout, and three optimizer steps. The default CLI policy
retains BF16 frozen base matrices while adapter parameters remain FP32.

| Run | Recorded losses | Saved adapter tensors | Nonzero B tensors |
|---|---|---:|---:|
| Qwen3-0.6B | 7.18275, 6.5133, 6.7586 | 224 | 112 / 112 |
| Qwen3-0.6B after adapter restore | 7.04583, 6.3985, 6.6932 | 224 | 112 / 112 |
| Qwen2.5-0.5B | 6.44372, 6.5798, 6.2640 | 192 | 96 / 96 |

All saved adapter values were finite. All 224 Qwen3 adapter tensors changed in
the continued run. PEFT loaded all three real-training adapters and recovered
their stored values bitwise. Continuing from an adapter starts a fresh optimizer;
this is not a claim of exact optimizer/RNG checkpoint resumption.

## Regression and packaging checks

- The full core suite passed **30/30**, with external HF and tokenizer fixtures
  enabled, so those tests were executed rather than skipped.
- GPT-2 small's Q8 path was rerun after the FP16 correction, which also affects
  subnormal Q8 block scales. FP32/Q8 training completed three steps each, and
  Q8 export/reload produced bitwise-identical values in all 48 adapter tensors.
  A dedicated tiny-scale Q8 regression checks that the base output is not halved.
- Tokenizer golden alignment passed all **28 cases**, covering GPT-2, Gemma,
  Qwen2.5 and Qwen3, including Qwen thinking tokens, whitespace and Unicode.
- Qwen3 was added to all eight combinations of attention streaming, activation
  checkpointing and frozen-weight offload, over three Adam updates, including
  untied heads, non-square projections and all-linear LoRA.
- Five model-specific example builds, their two-step synthetic suite, and their
  two-step real-weight WikiText excerpt suite passed. The existing GPT-2 QKV
  gradient correction remains covered in FP32 and Q8 modes.
- Installed public headers/CMake package built and ran an external consumer using
  non-square Qwen3 LoRA dimensions. The bundled JSON license is installed too.
- Qwen and GPT-2 small native Android arm64 builds passed with NDK 26.1.10909125 /
  API 29 / BLAS off, including the shared FP16 correction.
- A physical phone has not been connected for this updated build. No new Android
  execution, performance, energy, thermal or memory-saving result is claimed.

The exhaustive FP16 check compares finite values, signed zeros and infinities
bitwise with NumPy; all NaN encodings retain NaN classification. FP16 boundary
promotion is also retained in the hermetic architecture regression.
